# Audit Synthesis — Network Sync, May 2026

## TL;DR

The repo presents itself as a near-production multi-agent platform with Phase 3 mostly complete. The on-disk reality is:

- **Nothing currently builds end-to-end.** Backend has 69 TypeScript errors blocking `tsc`. Frontend Next build fails on a one-line lint error.
- **Most "implemented" services are scaffolds.** Roughly 8 of the ~25 backend services claimed as implemented in `CODEBASE_AUDIT.md` are production-capable. The other ~17 use `new Map()` as their system of record — security sessions, GDPR consents, AI cost budgets, workflows, content versions, backup inventories all evaporate on restart.
- **The Visual Workflow Builder I built this session is unreachable.** This Next.js app uses the **Pages Router** (commit `2f38d2e`), but I put the page at `src/app/workflows/page.tsx` (App Router). It's never served. `WorkflowCanvas` is never imported by any mounted page.
- **The frontend dashboard will runtime-crash** the moment a user clicks Social Accounts or Workflows: `_app.tsx` mounts no providers (no `AuthProvider`, `SWRConfig`, or `QueryClientProvider`), yet `useSocialAccounts`/`useWorkflows` still import from `react-query`. The "SWR migration" was incomplete.
- **There is a remote-code-execution path in production code today.** `POST /backup/restore/:recoveryPointId` has stub auth that hardcodes `req.user = { id: 'admin' }` and shells out `pg_dump`/`psql` with user-controlled paths via `execAsync` (a template-string shell call). Auth bypass + command injection = RCE.
- **8 backend routers have zero auth middleware imported at all** — workflows, AI cost, AI optimization, agent supervision, content management, analytics, context, cache. The "4 roles, 41 permissions" claim is honored only by `compliance.routes.ts`.

Migrations exist on disk for almost every service, but the services don't query them; the migration runner only registers 3 of 9 files; and the connection pool targets the `network_sync` schema while the migrations create tables in `public`. So even if a service were "DB-backed," the wiring wouldn't resolve.

Test coverage has regressed from 9.7% to **6.43%** — not because we removed tests, but because more suites now fail to even load (hard-required Redis/Supabase at module import).

This is recoverable. The drift is real but mostly mechanical, and the architecture underneath is sound. Below is the path.

## Roadmap to a strong finish

Sequenced by reversibility and blast radius. Each tier is a coherent merge unit.

### Tier 0 — Stop the bleed (Day 1, ~1 day of focused work)

Goal: app builds, no public RCE.

1. **Fix 69 backend `tsc` errors with one helper.** All are `req.query.x: string | string[]` widening. Add a `getQuery(req, name): string | undefined` in a `utils/http-query.ts` and refactor the 15 route files. Single-pattern fix.
2. **Fix frontend build:** remove unused `motion` import in `web-interface/src/components/auth/LoginForm.tsx:4`.
3. **Kill the two stub `authenticate` functions** in `src/routes/backup.routes.ts:13-17` and `src/routes/visual-workflow.routes.ts:30-34`. Import the real `authenticate` + `requirePermission` from `src/middleware/auth.ts`.
4. **Switch `backup.ts` `pg_dump`/`psql` calls from `execAsync` (shell) to `execFile` (no shell)** with arg arrays at lines 298, 324, 479, 490. Validate `destinationPath` against an allowlist regex.
5. **Wire helmet and rate-limit globally** in `src/server/app.ts`. Both are already in `package.json`.
6. **Refuse to boot if `ALLOWED_ORIGINS` is unset in production** — remove the `|| '*'` fallback at `app.ts:39-42`.

### Tier 1 — Make the frontend real (Days 2–3)

Goal: a logged-in user can actually use the dashboard without crashing, and can reach the workflow builder.

1. **Mount providers in `_app.tsx`.** Wrap children in `AuthProvider` + `SWRConfig`. Delete `QueryClientProvider` references.
2. **Finish the SWR migration** — convert `useSocialAccounts.tsx` and `useWorkflows.tsx` to `useSWR` (they still import `react-query`).
3. **Move the Visual Workflow Builder page to the right place.** This project is Pages Router. Move `web-interface/src/app/workflows/page.tsx` → `web-interface/src/pages/workflows.tsx`. Verify `WorkflowCanvas` is imported by the new file. Delete the orphaned `app/workflows/` directory.
4. **Wire `AuthContext` to Supabase.** Today it returns a hardcoded `dev@example.com`. Use the existing `web-interface/src/lib/supabase.ts` client; set/clear `localStorage.auth_token` from `session.access_token` so `workflowApi`'s Bearer header works.
5. **Implement (or remove) the missing Next API routes.** `useSocialAccounts` and `useWorkflows` call `/api/social/accounts`, `/api/workflows*` which 404. Either implement them as Pages-Router `pages/api/*` handlers that proxy to Express, or delete the hooks and call the backend directly.
6. **Document `NEXT_PUBLIC_API_URL`** in `.env.example` and the frontend README. Without it, the prod build calls `localhost:3001` from end-user browsers.
7. **Delete the "Coming Soon" stub pages** or label them with a real banner — don't ship pages with fabricated numbers.

### Tier 2 — Auth and persistence parity (Days 4–7)

Goal: every endpoint authenticated, every persisted thing actually persisted.

1. **Auth all 8 unauthenticated routers.** Add `router.use(authenticate)` at the top of each, plus `requirePermission(...)` on mutating endpoints: `workflow-management`, `ai-cost`, `ai-optimization`, `agent-supervision`, `content-management`, `analytics`, `context`, `cache`.
2. **Add zod validation at route boundaries.** Schemas exist in `src/types/typescript-types.ts` but are never `.parse()`d at entry. Pick the 10 highest-risk endpoints first (anything that writes or executes).
3. **Replace `Map` storage with PostgreSQL repositories** for the five services where data loss is unacceptable, in this order:
   1. `security.ts` (sessions, API keys, rate limits) — already has migration `005`
   2. `compliance.ts` (audit, consent, GDPR) — already has migration `006`
   3. `workflow-manager.ts` — already has migrations `002_perf` + `003_create_workflows`
   4. `backup.ts` metadata — already has migration `007`
   5. `content-management.ts` — already has migration `003_content_management`
4. **Fix the migration system.**
   - Resolve the duplicate-`002`/duplicate-`003` numbering by renumbering: `002a_social_accounts`, `002b_performance_indexes`, etc., or merging.
   - Update `scripts/run-migrations.js` to apply all files in `migrations/` in lexical order, not the three it currently knows about.
   - Pick one schema: either qualify every migration with `network_sync.` and confirm the pool's `db.schema = 'network_sync'`, or drop the schema and use `public`. Today they disagree.
5. **Replace `workflow-manager.ts:542` always-true condition evaluator** with a real expression evaluator (the visual executor already has one we can lift — minus the `new Function()` part).
6. **Replace `new Function(...)` in `visual-workflow-executor.ts:342`** with `isolated-vm` or a small allowlist-based evaluator. This is an RCE vector if any user input reaches transform config.
7. **Wire visual-workflow-executor action nodes** (line 231-252) to the actual platform services (`OpenAIService`, `TwitterService`, etc.) instead of returning synthetic success.

### Tier 3 — Test infrastructure & dependency hygiene (Days 8–10)
